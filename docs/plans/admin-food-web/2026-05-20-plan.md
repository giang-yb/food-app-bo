# 1. Context

**Problem:**
Build a complete Angular 19 admin panel for a food ordering web application. The system needs base UI components, admin layout, and CRUD pages for products, categories, orders, users, and promotions. Uses Tailwind CSS + Headless UI for styling, Supabase for backend and auth.

**Affected Modules:**
- `src/shared/components/base/` — Reusable UI components (btn, input, table, card, modal, badge, avatar, dropdown, spinner)
- `src/app/admin/layout/` — Admin shell (sidebar, header, admin-layout)
- `src/app/admin/pages/` — Dashboard, Products, Categories, Orders, Users, Promotions
- `src/app/core/services/` — Supabase service
- `src/app/models/` — TypeScript interfaces
- `src/app/admin/guards/` — Auth guard

**Non-Goals:**
- Customer-facing frontend (not in scope)
- Real-time features (WebSocket/SSE)
- Email/push notifications
- Payment integration

---

# 2. Constraints

**Language:** TypeScript
**Architecture:** Angular 19 standalone components + SPA routing
**UI Framework:** Tailwind CSS + Headless UI (Angular port via @headlessui/angular)
**Backend:** Supabase (Postgres + Auth + Storage)
**Database Schema:** users, orders, product_options, order_items, products, categories, promotions, promotion_products, reviews

**Rules:**
- Angular 19 standalone components (no NgModules)
- New components use `angular.json` paths alias (`@app/...`)
- Do NOT modify existing app.component.ts (except routing)
- Do NOT introduce new external deps without approval

**Performance Budgets:**
- Initial load: < 2s on 3G
- Table pagination: server-side, 20 items/page default

---

# 3. Conventions

**Angular Patterns:**
- Standalone components with `imports: []` array
- Signals for reactive state (`signal()`, `computed()`)
- `inject()` instead of constructor injection
- `toSignal()` from `@angular/core/rxjs-interop`

**Naming:**
- Components: `PascalCase` — e.g. `ProductListComponent`
- Files: `kebab-case` — e.g. `product-list.component.ts`
- Services: `PascalCase` ending with `Service` — e.g. `SupabaseService`
- Models: `PascalCase` ending with `Model` — e.g. `ProductModel`
- Interfaces: `PascalCase` — e.g. `Product`

**Tailwind CSS:**
- Use `@apply` for repeated utility classes
- Custom colors via CSS variables in `styles.scss`
- Responsive prefixes: `sm:`, `md:`, `lg:`, `xl:`

**Supabase Patterns:**
- All queries go through `SupabaseService`
- Real-time subscriptions use Angular signals
- Row Level Security (RLS) enforced server-side

**Error Handling:**
- Services return typed responses, never throw raw errors
- Components handle empty states and loading states explicitly
- Toast notifications for user-facing errors

## Data Structure: Product

```
Product {
  id:              string          — UUID, auto-generated
  name:            string          — max 255, required
  description:     string          — nullable
  price:           number          — decimal, required, >= 0
  category_id:     string          — FK to categories.id
  image_url:       string          — nullable, URL or null
  is_available:    boolean         — default = true
  product_options: ProductOption[] — has many
  created_at:      string          — ISO timestamp
  updated_at:      string          — ISO timestamp

  created_at:  string   — ISO timestamp

```

  user_id:         string      — FK to users.id

# 5. Target Architecture

**Components:**

```
AdminComponent (router-outlet)
├── AdminLayoutComponent
│   ├── SidebarComponent
│   ├── HeaderComponent
│   └── <router-outlet> (page content)
├── DashboardComponent
├── ProductListComponent
├── ProductFormComponent (add/edit)
├── ProductDetailComponent
├── CategoryListComponent
├── OrderListComponent
├── OrderDetailComponent
├── UserListComponent
├── UserDetailComponent
├── PromotionListComponent
└── PromotionFormComponent
```

**Interaction Flow:**

```
User navigates to /admin
  → AdminAuthGuard checks Supabase session
    → If no session → redirect to /login
    → If admin role → render AdminLayoutComponent
      → SidebarComponent (fixed navigation)
      → HeaderComponent (user info, logout)
      → <router-outlet> loads requested page

Page loads data:
  → Page calls SupabaseService method
    → Service executes Supabase query
    → Returns typed result or throws
  → Component handles loading/error/success states
  → Template renders with signals
```

**Key Decisions:**
- Auth guard in `canActivate()` route config — redirect to `/admin/login`
- Shared base components isolated in `src/shared/components/base/` — consumed by all pages
- SupabaseService as single entry point — all pages inject and call service methods
- Angular signals for state — loading, error, data all as signals
